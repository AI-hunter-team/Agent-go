# 项目总方案：由 AI 驱动的动态世界博弈游戏
*产品构思确认稿 v1.1｜项目名称待定*

> v1.1 相对 1.0 的修改（2026-10-30）：
> 1. 评分：首版只看**过闸机用时**（第十一章、第十二章补充规则）。
> 2. 单次决策的思考链长度**不超过 1024 token**（第八章）。

**一句话概述：玩家通过自然语言指导自己的 AI 角色，让它在一个持续变化、各方都有自身行为逻辑的世界中，自主判断、采取行动并完成目标。**

**核心概念：你拥有一个目标，世界拥有自己的意志。**

首个 Demo 以地铁站为场景，通过“买票—安检—过闸机”呈现完整机制。地铁是帮助用户快速理解产品的第一个场景，后续可以扩展到其他具有不同目标、环境与博弈关系的世界。

---

## 一、产品定位与核心体验

产品定位为**由 AI 驱动的动态世界博弈游戏**。

玩家不直接操纵角色的每一步，而是通过自然语言表达目标、原则、行动倾向和创意。角色理解指导后，在环境中自主观察、规划和执行，根据实际结果调整行动。

世界不会围绕玩家的计划运转。普通角色有自己的活动，通道有不同的通行效率，设备可能出现异常，其他角色的行为也会改变局面。玩家需要接受：即使事先有一个不错的方案，角色进入现场后仍然可能遇到意外。

产品希望形成三种核心体验：

- **指导的影响力。** 玩家能看见自己的一句话，如何影响角色的路线、判断和风险选择。
- **自主行动的惊喜。** 角色有空间自行解决问题，可能找到玩家没有明确安排的路径，也可能暴露令人意外的判断失误。
- **动态世界的博弈感。** 环境与其他角色不断变化，玩家需要通过观察和复盘，改进下一次指导。

游戏背后同时包含用户使用 AI 的能力差异，以及不同模型的能力差异。这些可以成为复玩、讨论和后续对比的内容，但产品面向用户时，首先呈现的是一个有目标、有变化、有后果的世界。

## 二、玩家的身份与控制方式

玩家是角色的指导者与策略制定者。角色是玩家在世界中的行动主体，负责把指导转化为具体行为。

每次开始前，玩家可以输入**最多 300 字**的自然语言指导，内容可以涉及：

- 希望优先实现什么。
- 如何权衡效率、稳定性和风险。
- 遇到拥堵或异常时如何处理。
- 哪些行为可以自主决定，哪些边界需要遵守。
- 希望尝试什么创造性的解决办法。

玩家不必掌握提示词术语，也不必写成程序。系统会把自然语言整理为便于 Agent 执行的指导。

角色始终拥有系统提供的默认任务提示词。如果玩家什么也不填写，角色也能按照正常流程完成任务，例如买票、排队、安检、刷卡过闸。玩家的输入是在这一基础上赋予角色不同的策略和倾向。

300 字只限制玩家输入。系统规则、基础工具说明、固定场景信息与局内观察，不占用这份额度。

**当前默认采用赛前指导、局内自主行动的方式。** 玩家在运行中主要观看角色和关键决策，不通过频繁点击代替角色判断。是否增加局内有限干预，留待后续讨论。

## 三、一次完整体验如何展开

**第一步：了解场景与任务。**

玩家进入某个场景，了解任务目标、基本规则和公开信息。地铁 Demo 的目标是完成买票、安检并通过闸机。

界面解释正常通行方式，但不会主动列出所有创造性解法。

**第二步：提交指导。**

玩家填写最多 300 字，也可以直接使用默认方案。

角色 Agent 将输入整理为更明确的执行指导，与系统规则和固定信息融合，生成初始行动方案。整理过程应保留玩家原意，不擅自增加玩家没有表达的偏好，更不能赋予角色额外权限。

初始方案只是开局计划，后续允许根据现场信息调整。

**第三步：进入世界并自主行动。**

角色按计划移动和交互，在可观察范围内获取实时状态。到达关键位置、完成某项动作或收到重要事件后，重新判断下一步。

**第四步：观看选择与后果。**

玩家看到角色去了哪里、选择了什么，以及实际产生的结果。关键时刻适当展示简短说明，例如：

> “近处队伍人数少，但预计处理时间更长，准备前往另一通道。”

展示内容帮助玩家理解决策，不需要呈现长篇内部推理。

**第五步：结束与复盘。**

任务结束后，系统整理行动路线、关键选择、耗时、异常事件和结果，帮助玩家理解本局过程。

玩家根据复盘修改指导，再进入下一次尝试。产品的长期体验由这一循环逐步形成。

## 四、世界如何运行

世界拥有独立于玩家意图的状态与规则。

首版中，除玩家角色以外的所有角色，都由环境程序控制，包括普通乘客和保安。程序负责排队、移动、服务处理、异常事件和相关响应。

例如：

- 不同乘客具有不同的通行速度和处理时间。
- 不同通道具有不同的检查效率。
- 某个通道可能临时停用。
- 乘客可能在安检时遇到问题，需要复检。
- 角色影响他人或违反规则后，可能引发乘客和保安的反应。

这些变化应当具有可解释的原因，不能只是为了阻碍玩家而随机弹出惩罚。

后续第二版计划探索由 **Boss Agent** 接管或协调保安、NPC 等环境行为，使世界产生更丰富的应对。具体是一个 Agent 统筹，还是多个 Agent 分别控制不同角色，尚未确定。

无论环境由程序还是 Agent 控制，**实际状态与最终结果都必须遵守统一规则**。环境角色可以判断和行动，但不能凭一句描述改变已经发生的事实。

## 五、固定知识、现场观察与信息限制

角色可以提前知道固定信息，例如公开地图、道路连接、售票处、安检口和闸机的位置，以及基本通行规则。

实时变化的信息需要通过现场观察获得。角色不能在开局时就知道远处所有队列长度、设备状态或其他角色的行动。

系统为角色设置可观察范围。接近一个节点后，环境提供该范围内能够获得的信息，例如：

- 附近队伍的人数。
- 可观察的 NPC 特征。
- 通道当前是否开放。
- 设备或工作人员的处理效率。
- 正在发生的异常。
- 自己当前动作的实际结果。

“到达节点后收到场景信息”指的是**获得该位置可感知的信息**，不是获得整个世界的全部状态。

广播、警报和附近动静也可以成为信息来源，但需要符合声音覆盖或事件传播规则。其他角色尚未执行的计划、不可见位置的实时状态，不自动公开。

这种信息限制让探索、接近、观察和判断都有意义。

## 六、耗时范围与不确定性

环境可以向 Agent 提供预计耗时范围，帮助它判断，但不直接告诉它最优选择。

例如，某类乘客的通行时间处于一个区间，某条安检通道的单次处理时间处于另一个区间；发生复检后，会增加一段预计耗时。

角色需要结合人数、人员组成、移动距离和异常风险，自行比较方案。人数少的队伍不一定更快，设备处理快的通道也可能需要更远的绕行。

这些范围需要有明确含义，区分：

- 单个乘客的处理时间。
- 设备或工作人员的服务时间。
- 当前动作的预计剩余时间。
- 异常事件带来的额外耗时。

**随机性是后续明确保留的方向，Demo 不要求全部实现。**

后续可以让实际耗时、NPC 行为和部分事件在规则允许的范围内变化，增加运气和不确定性。同一套指导可能在不同局面下产生不同结果，玩家需要追求对变化的适应能力。

测试阶段可以先采用固定情景，确认角色能理解信息、正确行动，再逐步加入随机性。若后续用于竞技或能力对比，则应通过多次测试和可比条件，减少单局运气对结论的影响。

## 七、创造力与开放解法

**创造力仍然是产品的重要方向，并从首版设计中保留入口。**

玩家可以通过自然语言提出常规流程之外的行动意图。角色结合现场条件，决定是否尝试；系统将意图转换为可检查、可执行的行动，再根据世界规则反馈结果。

面向玩家时，不主动展示完整的隐藏能力或解法清单。基础交互需要清楚，具体创造性路径则留给玩家发现。

这一机制需要遵守三个原则：

**第一，表达可以开放，结果必须落地。**  
角色提出某个行动后，必须真正影响位置、资源、对象或环境，不能只生成一段“行动成功”的文字。

**第二，创造性行动具有条件、代价和后果。**  
能否执行，需要结合空间、资源、目标和规则判定。影响其他角色时，也可能引发他们的响应。

**第三，失败反馈应当有助于理解。**  
对于不支持或条件不满足的行动，应明确说明限制。相近含义的不同表达，应尽量获得一致理解，避免变成猜特殊口令。

首版不承诺无限生成能力。具体支持哪些机制，仍需结合开发范围确定。此前讨论的飞行、滑行、挖地道等属于内部探索示例，不等于全部进入 Demo。

## 八、Agent 的决策与动作执行

Agent 负责理解、规划和选择，环境负责执行、校验和维护状态。

简要流程为：

**获得观察 → 结合指导与局内记忆判断 → 调用动作工具 → 环境执行 → 接收结果 → 调整计划。**

基础操作包括移动、等待、排队、离队、换队、买票、安检、刷卡，以及停止或替换当前动作。创造性尝试通过额外入口提交。

底层可以负责沿路线移动、处理碰撞和避免穿墙，但战略选择仍由 Agent 作出。例如，绕开近处障碍属于动作执行，决定换一条安检通道属于策略判断。

首版主要采用事件触发决策，包括：

- 到达关键位置。
- 当前动作完成或失败。
- 通道关闭等重要状态变化。
- 收到与自身有关的异常信号。

暂不将固定两秒调用一次模型作为必要机制。

**本稿按前面讨论的暂停方案作为 Demo 基线：Agent 决策时，整个模拟世界进入暂停式“子弹时间”。** 玩家角色、NPC 和事件计时同步暂停；模型返回有效决定后，世界恢复，角色继续原动作或切换动作。

因此，“是否停下来”指的是恢复运行后，是否取消原有动作。真正的一边移动一边调用模型，可以作为后续异步运行机制继续探索。

**单次决策的思考链长度不超过 1024 token。** 每次决策调用模型时，思考与输出的总长度以 1024 token 为硬上限，由调用参数强制执行，不依赖模型自觉遵守。超出上限未能给出有效动作的，按决策失败处理（重试或执行保底动作）。这一限制同时控制单局成本和玩家等待时间，也让不同玩家、不同模型在相同的思考预算下比较。

## 九、局内记忆、反馈与复盘

角色保留本局必要的观察、当前计划和行动结果。例如，刚发现某通道停用后，不应立即忘记并再次前往。

首版不做自动累积的跨局经验，也不让角色通过隐藏历史逐渐获得额外优势。

每局结束后，保留供玩家查看的报告和记录，再清空角色运行所用的局内记忆。下一局使用系统规则、当前场景和玩家新提交的指导。

复盘应围绕可核对的事实组织：

- 当时观察到了什么。
- 采取了什么动作。
- 实际发生了什么。
- 时间主要消耗在哪里。
- 哪些指导得到体现。
- 哪些地方可能值得调整。

需要避免仅凭模型的一段解释，就认定某句话一定导致了某个结果。必要时，通过相同情景下的不同指导进行对照。

后续可以增加指导版本保存、同一情景重试与关键节点回放，让玩家更容易看见自己的改变是否有效。

## 十、竞技、模型对比与长期发展

首版先验证单个玩家角色与动态环境之间的交互，不急于加入多人匹配。

后续可以逐步发展两类体验：

**用户之间的策略博弈。**  
在统一模型、工具权限和资源预算下，不同玩家指导的角色进入同一场景竞争。奖杯、实力匹配和段位仍保留为后续方向，具体规则尚未确定。

**不同模型的行为对照。**  
让不同模型在相同任务、指导和环境条件下运行，观察它们在规划、工具使用和突发应对上的差异。对比结果限定在具体场景和配置内，不直接等同于模型综合能力排名。

这两类内容可以服务于游戏的讨论和传播：同样的世界，为什么不同人的 Agent 会作出不同选择？同一份指导，为什么不同模型表现不同？

更长期的扩展方向，是加入具有不同任务结构的新场景，以及更丰富的环境角色。场景需要带来新的决策问题和博弈关系，而不仅是更换外观。

## 十一、首版 Demo 的交付边界

| 项目 | 首版范围 |
|---|---|
| 场景 | 一个地铁站 |
| 目标 | 完成买票、安检并通过闸机 |
| 玩家角色 | 一个由大模型驱动的 Agent |
| 环境角色 | 程序控制的 NPC 与保安 |
| 表现方式 | 二维点、线、面与必要状态文字 |
| 玩家输入 | 默认指导＋最多 300 字补充 |
| 开局准备 | 整理指导，生成初始方案 |
| 信息机制 | 固定知识＋范围内实时观察 |
| 现场复杂度 | 队列差异、通道效率和少量异常情景 |
| 决策机制 | 关键节点与事件触发，思考时暂停世界；单次思考链 ≤ 1024 token |
| 评分 | 过闸机用时（世界内时间，不含思考暂停）；失败无成绩 |
| 失败条件 | 限时内未过闸机；违规被保安发现 |
| 创造力 | 保留入口，支持范围另行确定 |
| 结束反馈 | 任务结果、关键行动与基本复盘 |
| 暂不要求 | 3D、多玩家匹配、奖杯体系、Boss Agent、完整随机事件系统 |

首版需要证明的核心是：**默认角色能够完成任务；不同指导能带来可观察的行为差异；环境发生变化后，角色能够获得信息并调整行动；所有结果与环境状态一致。**

## 十二、技术思路简述

技术实现可以分为四部分：

- **场景展示层：** 用二维方式展示地图、角色、队列和关键状态。
- **环境模拟层：** 管理位置、通行条件、队列、NPC、事件和计时，维护唯一有效的世界状态。
- **Agent 运行层：** 接收指导与观察，维护局内记忆，调用模型并输出动作。
- **记录与复盘层：** 保存观察、动作与事件，生成结束报告，支持后续对照测试。

模型首先通过结构化数据理解环境，通过受约束的工具执行动作。首版不依赖看截图操作，也不允许模型任意修改环境代码。

具体模型供应商、前后端框架和后续 3D 技术栈尚未确定。此前讨论的相关技术仍只是候选。

**补充规则：失败条件、计时与观察限制。** 首版设置几分钟的任务限时，具体时长后续测试确定；倒计时结束仍未通过闸机，角色即死亡，本局失败。角色实施违规行为后，若被保安发现，同样立即判定死亡，无须再经过追捕或抓获。发现判定结合保安观察范围与视线遮挡：角色进入观察范围且违规行为可被识别时触发；若成功避开保安视线或利用遮挡躲过观察，则不会仅因系统记录了违规就自动判负。角色自身的观察也考虑遮挡，不能透过墙体或障碍获取实时信息。模型思考期间暂停世界与任务倒计时，思考耗时不计入总限时。**评分规则：首版只看过闸机用时**，即从开局到角色通过闸机所经过的世界内时间，越短越好；思考暂停不计入。倒计时内未过闸或被判负的局没有成绩。用时以外的指标（违规次数、决策次数等）只在复盘中展示，不参与评分。首版异常事件与创造力机制以目前讨论的基础能力为范围，不额外扩展新机制；具体实现项目、参数与支持边界在开发前明确。
