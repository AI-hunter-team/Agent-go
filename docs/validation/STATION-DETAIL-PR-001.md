# STATION-DETAIL-PR-001：站内设施与世界生成 PR 整合验证

## 范围与来源

- 在既有 PR #68 的 `55dab41` 和 CONTROLROOM-005 修改之上，整合 `codex/station-detail-v1` 的 STATION-DETAIL-001 增量；[任务简报](../tasks/STATION-DETAIL-PR-001.md)记录来源快照和路径边界。[来源验证](STATION-DETAIL-001.md)是原工作树的历史结果，彼时以到达站台结算，不能当作本次登车规则的成绩。
- 默认新世界使用站内细节 `metro-v2`：45 类原创资产、各两种变体，共 90 个内嵌 PBR 贴图的 GLB，48,006,568 字节；展厅共有 107 个展品及六类空间组合。逐一核对 90 个 GLB 的长度、格式头和清单 SHA-256，全部一致。纹理中间文件不入库，复建方式见[资产说明](../../design/station-detail/README.md)。
- 将物件占地同时用于世界碰撞、可视化与地图；站台屏蔽门跟随模拟车门位置并在停靠时保持开启。保留实际进入车厢结算、150 秒默认时限、安保及队列规则。
- 两份历史 `metro-v1` 摘要均可重建，未知摘要拒绝；对来源快照和本 PR 旧版分别对照 50 个种子，摘要均 50/50 一致。规划模型、会话、已保存世界恢复按选定版本使用同一公开地图。旧报告继续使用记录中的地图。

## 软件和离线验证

- Node 24 / npm 12：`npm run typecheck`、`npm test`（`VITEST_MAX_FORKS=2`、`VITEST_MIN_FORKS=1`，103 文件 / 899 项）、`npm run build`、`git diff --check` 通过；构建有既有大块提示。
- 首次完整测试 898/899 通过，NPC 接口测试因 Windows 随机临时端口被 Node Fetch 禁用而出现 `bad port`。已让该测试避开 Fetch 禁用端口，随后完整复跑 899/899 通过；未更改业务行为或减少断言。
- 首次远端 Ubuntu 运行中，1000 种子测试因 `metro-v2` 增加实体布局校验，超过原 180 秒测试预算（其余 898 项通过）。已将该单项测试预算提高至 360 秒，保留全部 1000 个种子、断言和让出事件循环；游戏时限未改变。最终远端检查状态以 PR 为准。
- 新版 1000 个固定种子通过布局与确定性检查；另检查安检队列前六个槽位，0 个非法占位、0 个与售票或其他安检队列交叉；含实际登车的空载基准最长约 77.65 秒。
- 默认规则下 50 种子离线完整对局：43 局实际登车成功、7 局超时；与整合前 PR 基线成功/失败分类完全一致，种子 27 成功耗时从 131.9 秒变为 129.7 秒，其余耗时一致。此结果不等于真实模型验收。
- 旧版两种摘要的保存世界重建、规划输入与会话绑定、错误摘要拒绝，以及新世界登车、隔层电闸、队列和胜利镜头均有专项测试。

## 浏览器与资源

- 生产构建、伪模型/离线流程：1440×900、768×900、390×844 的首页次级按钮均为 `rgba(246, 243, 234, 0.88)`，主按钮仍为黄色；世界管理、角色选择与创建界面可打开返回，无页面异常。
- 390×844 浏览器模拟尺寸：创建种子 2 世界、入站、暂停、整站地图、实际登车（134.4 秒）、复盘与轨迹、同世界和新世界重试通过，无页面脚本异常。
- 展厅在 1440 与 390 宽度加载全部 90 个正式模型；绿植、垃圾桶及休息角可展示，20 次切换可操作。拦截新增素材清单时本地模型降级可用；390 宽度无横向溢出。
- 在浏览器 IndexedDB 写入两个固定旧世界夹具，分别选择原工作树与当前 PR 的 `metro-v1` 摘要，均进入角色准备页且镜头使用相应摘要；无页面脚本异常。
- 同设备 Edge 156、RTX 5090 Laptop、1440×1000 / DPR 1、标准画质、种子 1 入场后采样 60 秒：P95 帧间隔 17.3 ms，较整合前 PR 的 17.5 ms 未恶化，平均 60.35 FPS。采样点绘制调用 656→862、三角形 1,226,992→1,397,142、几何体 420→671、纹理 96→181；GPU 和内存成本需要在其他设备复核。采样前后同一角色和镜头实例，最终 85.2 秒实际登车成功。
