## 已实施接口与流程

- 客户端阶段：lobby / character / guidance / planning / plan / launch / watch；watch 中运行器 ended 展示复盘。设置是 Radix 受控抽屉，关闭返回当前阶段。
- `POST /api/journey/prepare` 输入为 `JourneyInput`：sceneId=metro、seed、settings、guidance、autonomous、runId；拒绝未知字段。返回 `JourneyPreparation`：id、model、normalized、plan（understanding/actions/adjustment）。Responses 使用严格结构化输出，空指导也发起规划，不传隐藏世界状态。
- 准备结果在服务端限100条、闲置10分钟失效；按令牌、模型实例/参数、runId、场景、种子、指导与规则绑定。`POST /api/session` 增加可选 preparationId、sceneId、seed，校验后消费一次，由服务端方案覆盖客户端 normalized；不匹配返回409并要求重新规划。旧调用不带 preparationId 时沿用原行为。
- 只改角色外观保留方案，确认后可返回方案页；改其他准备依赖使方案失效。离开规划页面取消客户端请求，晚返回结果不得改写新状态。服务器模型调用仍受既有20秒超时限制，不承诺供应商已停止计费。
- 开局资源与相机握手通过后创建运行器，未用固定延时启动。相机碰撞仍以角色中心为起点，画面构图偏移不改变碰撞或模拟坐标。
- 报告新增可选 journey，包含场景、角色标识/名称、实际模型、初始方案、自主模式和准备耗时；自定义角色只记custom标识，不记Blob URL/本机路径。实际决策响应返回模型名时优先记录响应名。
- 复用已有自定义GLB预检、IndexedDB存储、朝向和回退；选角缩略图按需渲染真实模型。保安外观放在高级设置；原工作区NPC未提交修改保留不变。
- 顶部播报使用有界优先队列，完整事件/思考/沟通按需展开。计时、动作与世界结算沿用模拟器；初始方案仅为策略。
