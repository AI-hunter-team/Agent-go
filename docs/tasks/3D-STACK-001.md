## 候选建议与取舍

以下是执行者建议，等待讨论，不是用户已经批准的技术决定。

- **渲染优先候选：Three.js + React Three Fiber + Drei，沿用 React / Vite / TypeScript。** Three.js 提供 3D 渲染，R3F 用 React 组织场景，Drei 提供模型加载等辅助能力；相机跟随、避障和游戏规则仍需项目实现。
- **图形路径：先以 WebGL2 为基线。** 第一版暂不以 WebGPU 为必要依赖，不承诺未实测的帧率或设备覆盖。
- **版本配套：** 官方文档将 R3F 8 配对 React 18、R3F 9 配对 React 19。实施前需核对 Three.js、Drei 等的 peer dependencies 并锁定兼容组合；不直接安装全部 latest，也不在本讨论升级依赖。
- **另一 Web 候选：Babylon.js。** 官方提供相机、动画、GUI、碰撞及物理集成等较完整的引擎能力；本项目采用它的收益需与现有 React 场景组织方式和迁移成本比较。
- **UI 优先候选：Radix Primitives + 自定义 CSS / CSS Modules。** 用无样式组件处理弹窗、提示、滑块和焦点交互；计时、状态、事件等 HUD 按游戏美术设计。优势是视觉自由，代价是需要自己完成样式和布局。
- **UI 备选：shadcn/ui + Tailwind CSS。** 获取可修改的组件源码，较快搭建设置、指导输入与复盘；需定制皮肤以适配游戏，而非直接把默认样式当作美术规范。
- **UI 备选：Mantine。** 现成组件及主题、Styles API 适合快速建设功能较多的设置和工具面板；是否更合适取决于功能交付速度与定制视觉的优先级。
- **UI 分层：** 固定 HUD 使用覆盖在 3D Canvas 上的 React DOM；少量角色标签可用 Drei Html。大量远处标签需另做裁剪和性能验证。
- **模拟与画面：** 现有地面坐标映射到 3D 的 XZ 平面，以 Y 表示高度；保留规则、时间、排队与判罚的唯一模拟来源。固定模拟步与画面刷新分离，通过插值平滑展示，不能用每帧 React state 更新所有角色。
- **物理与导航：** 单层第一版优先复用已有导航和规则阻挡；Rapier 作为后续刚体、推挤、掉落等需求的候选。显示模型、碰撞/视线阻挡与导航边界必须保持一致；添加物理或多层空间时另行确定状态归属与消费者迁移。
- **资产：** 优先接收 GLB / glTF 2.0，统一米制、竖直轴、朝向、角色脚底原点与动画片段命名；简单几何体和正式模型通过同一个实体表现入口替换。展示网格与逻辑边界分开管理，替换前核对尺寸、遮挡、材质与动画。

## UI 视觉细化提案

基于用户已确认的视觉优先级，建议继续采用 Radix Primitives + CSS Modules / CSS 变量。下面是待讨论的设计建议，不是已确认的交互规范或验收标准。

- **视觉语言：** 延续“现代主义交通剧场”，以交通导视、站牌和票据为参考；米白、炭黑为底色，赭黄作强调，灰绿作辅助；使用清晰字级、细分隔线、几何图标和小圆角。
- **观战页：** 场景占主要空间；顶部显示计时、运行状态和流程标记；右侧显示当前行动与最近决策摘要；最近事件放在小面板，完整日志按需展开。布局沿用单个玩家角色的现有范围，不从历史概念图引入四人竞技、体力或预测进度。
- **开局与复盘：** 指导输入可借鉴任务票据，复盘可借鉴行程记录；信息保持可编辑、可阅读、可导出，具体交互在实施任务确定。
- **组件边界：** 状态栏、事件条、行动卡和基础按钮按项目视觉制作；Radix 处理弹窗、提示、菜单和滑块等交互。固定 HUD 使用 React DOM，场内标签只保留必要信息。
- **动效与可读性：** 第一版优先用 CSS 完成展开、切换和提示动效；持续显示的文本保持清晰对比。界面动画与模拟时钟分开设计，不能因界面动效改变思考暂停、计时或结算规则。
- **建议的首个原型：** 单层站厅几何体、角色占位、第三人称跟随和主要 HUD，验证场景可读性、镜头遮挡及 UI 输入与相机操作的冲突；正式资产替换与性能验收另列范围。
