# CUTIN-PERMISSION-001：用户提出社交策略后才开放插队协商

状态：实现及软件验证完成（2026-10-31，Asia/Shanghai），采用本地快进移交。负责人兼集成人：本次 Codex 会话，串行开发；分支 `codex/cut-in-guidance-gate`，基线为当前试玩版本 `7148c44`，复用空闲隔离工作区。保留原试玩目录既有未提交文档与模型配置；不修改已经发布的 PR #13。

用户要求：未在指导中提出相关思路时，默认不展示或触发插队工具，由用户自己想到。用户进一步明确“和前面乘客商量”“向 NPC 求助”也算提出思路，不要求出现“插队”二字；仍需 NPC 同意后才能改变队列。空白、“赶时间”“逃票”不开放；明确禁止优先，不从模型整理结果推导权限。

- 允许范围：共享指导权限与整理结果过滤、两供应商的提示/工具选择与返回校验、NPC HTTP 与 Runner 执行校验、直接相关测试/文档。所有消费者由同一会话协调。
- 边界：只控制请求让位/插队协商，不修改翻闸、NPC 同意算法、设施、难度或保安。原始指导在开局时确定权限，模型新增点子、工具参数和未经绑定的 NPC 请求不能授予权限；未开放时不给出“改用 request_cut_in”的提示。
- 实现约定：使用可测试的保守文本规则，识别明确插队意图或面向 NPC/乘客的求助协商；普通闲聊和背景描述不开放。禁止语句优先；含糊表达保持关闭。默认模型上下文移除专用操作说明及工具，整理结果不主动补出该策略。报告 Debug 参数记录是否开放。
- 验证：先写默认/允许/否定/间接求助、归纳不能越权、两模型请求和伪造返回、API 无会话/未允许/已允许、执行层绕行与 NPC 调用数回归；完整类型/测试/构建/diff 和本地浏览器检查。没有付费模型调用或远端推送授权。本地移交后新局生效；结果见 [验证报告](../validation/CUTIN-PERMISSION-001.md)。
