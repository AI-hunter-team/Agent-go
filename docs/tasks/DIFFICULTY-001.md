## 设计与接口

- 用户选择可配置方案；直接提高默认难度和只给分析结果作为其他方案保留在对话，不作为本次交付。
- `GameSettings={timeLimitSeconds,extraQueuePeople}`；默认 180 秒 / +0 人，保持旧场景。时限为 60–300 秒整数，人数为每条开放队列额外 0–8 人整数；界面提供常用组合和独立数字输入，提交前校验。
- “额外人数”应用到所有初始开放设施，包含原本为空的队列；不向初始故障设施添加乘客。额外乘客类型通过独立的种子随机数生成，不扰动原背景客流生成顺序。
- 参数在每局 Engine 构造时复制冻结。预览、重新开局、同条件重试、模型会话和提示词、观察剩余时间、UI 计时、Debug 和 JSON 报告均使用本局参数；旧调用/旧报告省略配置时兼容默认值。
- API session 新增可选 settings，拒绝无效数值和未知字段，绑定本局快照。模型不能自行改写时限或队列。
- 对照使用离线守序 Agent 与固定种子集合，比较时限/人数组合的通关率、耗时与等待；不将离线结果冒称 DeepSeek 通关率。
