## 产品与依据

用户确认：每局换一座车站、事件也可不同；保留画风，真实空间与设施摆放优先；不把找路作为难点。地下双层岛式、紧凑比例、默认150秒及已有时限选择、现有交互是本轮范围。商店交易、寄存、电梯操作、工作人员作业和换乘/高架/侧式站台不在本轮。

## 静态世界与各局运行

- `WorldDefinition` 保存生成器版本、种子、地图摘要、楼层、区域、设施/队列、物品点位、人物锚点、设备房、细节组合与主题。实例在运行时冻结。
- `metro-v1`：站厅标高0、站台-6米；同层二维导航，楼梯/扶梯连接上下层。`openings`表示真实楼板开口，`openingBlocks`表示开口内不能当平地行走的范围，入口踏步保留接近空间；两者来自同一连接器。楼梯准入即切入连接器碰撞层，避免上层等待者阻塞已下楼的乘客。角色的 `floorId` 和轨迹的连接器、进度、高度使模拟、渲染、回放一致。楼板阻隔跨层视听和互动。
- `metro-v2`：在上述车站上确定性地放置共享的站内细节、实体占地和遮挡；新建世界默认使用此版本。旧版世界按保存的版本重建；两份历史 `metro-v1` 摘要均可恢复，未知摘要仍会被拒绝。资产与构建方式见[站内设施说明](../../design/station-detail/README.md)，整合结果见[验证](../validation/STATION-DETAIL-PR-001.md)。
- 每个 World 有独立移动和导航服务，缓存不跨地图共享。模型通过公开静态地图认识楼层、区域、设施、物品点和导航目标；观察继续仅含现场可见的人物、物品、状态及队伍。
- 中央付费区、侧向服务带、双端入站三类生成规则；大厅尺寸、入口、连接器位置、设备数、柱网、装修与细节变体从带种子随机流产生。双端设施标明入口归属，乘客不选择另一侧不可达队伍。
- 售票机3–5、安检3–4、进站闸机4–8。排队预留基准容纳4名大件行李乘客；服务出口按设备朝向计算。扶梯候梯预留折线空间，保留容量、FIFO和办理时间。
- 生成验证包含边界、各类设施数、基准路线可达、各队列及服务出口空间；路线按现有服务上界估算不超过90秒。最多尝试20个候选，失败使用校验样板并保存原因。

## 与主线登车规则整合

用户在 WORLDGEN-PR-001 整合时确认：生成车站和现行主线一样，以实际进入车厢作为胜利终点；站台只是中途，时限仍默认150秒。原 WORLDGEN-001 及其验证报告所述到站台结算和成绩是当时的历史快照，旧报告继续按记录显示，不追溯改写。详细整合与验证见[任务简报](../tasks/WORLDGEN-PR-001.md)及[验证报告](../validation/WORLDGEN-PR-001.md)。

生成列车的编组、车门中心和车体尺寸由渲染与模拟共用；公开地图提供本局车门接近点，只有沿车门的受控路径进入车厢才结算。站台外普通步行仍受边界限制，跨层不可直接到达车门。空载路线校验增加了站台到车门及车厢过道的距离。墙边电闸按实际入口派生，静态可见且仅能在站厅操作；不添加隐藏动态信息。

安保沿用主线平衡规则：生成站在实际安检设备的外侧两条通道配置安检员，中间通道仍正常提供服务；安检员的闲置视野和收到提示后的关注状态也与主线一致。生成安检队列依据设备方向分流，避免与相邻安检队列及售票机队列交叉。

生成站安检队列在售票银行程区前转弯，留出设备和行李空间；受阻时允许队首沿障碍重新对准通道，旧站队列行为保持原路径。此调整不改变世界布局、随机流、生成器版本或地图摘要；本局的实体轨迹和成绩仍由模拟器结算。

## 入站通道（WORLDGEN-002）

用户追加要求：主角从向下的楼梯进入车站，只制作通道。[任务简报](../tasks/WORLDGEN-002.md)及[验证](../validation/WORLDGEN-002.md)记录本轮增量。

- 每座生成车站的A/B口均有上端、楼梯脚、站厅接入点和包络；主角从A口楼梯上端约+4米开始，连续走到标高0的站厅，再触发首个Agent决策。默认入站约6.6秒，计入原有150秒，不追加找路操作。
- `entrances`为WorldDefinition可选字段，公开地图和报告携带相同数据；`entry:*`表示入站连接器，`entering`活动记录进度，轨迹用`connector=entrance`及entranceId标记。两层车站本身不变，不生成地面街景。
- 开局已有队列、工作人员和候梯者保留。开局后新增普通乘客从上端有顶盖的通道深处进入，入口被占用时延后；到站厅后继续原购票、安检、过闸及生活行为。生成地图不再在付费区内部定时补刷乘客。
- 通道具有墙体、扶手、照明、门洞及标识；主角和乘客使用同一条空间路径。3D按入口精确切开外围墙，镜头碰撞使用同一门洞；二维图和回放的范围扩展到通道，入站演员不会因显示层交接闪现。
- 无入口数据的旧地图/旧报告走原路径。显式Scenario覆盖仍用于从站内定位的测试/回放；正式新旅程使用入口。

## 正式模型与表面

生成场景已接入本项目米制青绿列车模型，并补建参数化石材楼梯、玻璃金属扶梯、轨道/枕木/线缆、盲道和8类设施细节。优先复用正式站厅纹理，缺失表面以原创固定配方生成颜色/法线/粗糙度图；不依赖在线图库或外部工作区。素材清单、复建、比例、贴图密度与资源归属见[素材说明](../../design/world-generation/README.md)，实际验证见[WORLDGEN-003](../validation/WORLDGEN-003.md)。仅影响展示，地图摘要和模拟行为不变。

## 日常状态与细节

8类组合：入口公告、售票服务窗口、安检工作台、闸机导向、楼扶梯提示、候车座椅站名、便民设备、设备房消防检修。每类2种变体，实体占地及遮挡在静态世界中定义，墙地面和主要设备复用正式素材。

生成地图的初始基础队列每设备抽样0–2名普通乘客，再增加当前设置固定的额外3人。该基础分布平均值为1，不改变额外人数或150秒时限。设备故障规模和事件时刻保留，安检停用与复检目标按本局实际设备从独立流抽样；默认情景不再自动熄灯，仅主动操作电闸才触发全站熄灯。旧情景仍使用旧基础队列与事件目标。

少量非排队乘客在入口公告旁查看信息、短暂停留或等候同行者，结束后继续行程。停留点与主导航目标分开；排队、服务、失能和警戒反应优先。离线规则Agent可比较可见队伍，在预计节省超过12秒时有限换队；没有使用隐藏队伍或未来故障。

## 接口、报告与兼容

旅程准备/会话请求可携带 `world: { generatorVersion, layoutHash }`，配合已有seed由服务端复建并校验；准备后更换地图需重新准备，模型工具枚举、Boss公开节点与取物点也随本局地图变化；服务端Boss使用会话绑定的公开地图，旧接口不携带world时仍使用旧布局。

旧 Engine / GameSession 构造调用保留 `legacy-v0`。正式页面通过 GameSession 的生成开关创建新车站。新报告保存实际静态世界和分层轨迹，JSON中不保存运行时函数；读取时依据报告内区域重建空间查询，不重新抽样地图。旧报告沿用既有兼容处理。

类型与API消费者由本任务串行统一修改。失败降级使用同一生成地图；正式素材加载完成后首次显示。模拟与外观随机流分离，换装饰不会抽取新的客流或事件。

## 休息室与创建世界（CONTROLROOM-004）

首页为固定3D出发休息室，03轻快品牌由同源矢量轮廓生成真实立体字；房内仅双人座椅、边几/杯子、壁灯、滑门与侧通道。默认相机完整展示品牌、人物及入口，窄屏另有构图。操作台与室内沙盘已撤下；旧实现历史见[CONTROLROOM-001](../tasks/CONTROLROOM-001.md)。

创建世界打开独立工作界面；960像素以上左右分栏，窄屏上下滚动并保留确认/返回操作。左侧3D预览可拖动、缩放、键盘按钮旋转和复位，并可切B1/B2共用平面底图；右侧填写名称和随机/数字/文字种子。预览只使用静态WorldDefinition，没有现场人物、队列或未来故障。预览独立挂载/释放，休息室主Canvas、角色与摄像机不重建。三维预览失败可回退同地图平面图并重试。

本机世界列表通过IndexedDB保存名称、原始/数值种子、生成版本/摘要、旅程偏好及角色ID；支持重命名、删除和重新进入，不保存进行中对局或凭据。数字保留原API值，文字经trim/NFC和UTF-8 FNV-1a映射到非零uint32。版本不兼容时先关闭列表，显示创建当前版本副本入口，保留原记录。

大厅“角色外观”无需世界，确认后以`agent-go.default-character.v1`保存默认角色ID，取消恢复原选择。新世界继承默认外观；选择/继续已有世界恢复该世界偏好，旅程内修改只保存到该世界。默认偏好与世界库格式相互独立；自定义GLB仍使用既有模型文件管理，缺失时回退大肥鱼并提示。

确认规则和方案后，组装车站并等待资源/会话就绪，再打开门。主画布、主角根节点及摄像机持续存在，约8秒非计时启程结束时在A口楼梯顶部调用startPrepared；默认150秒与约6.6秒实际下楼计时均保留。启程可3倍加速、取消后回到准备状态；展示过程不修改世界事实或随机流。

正式素材失败使用项目本地模型；WebGL不可用保留品牌、表单、平面预览及2D游玩。声音、显示、模型等沿用设置入口。范围与实际结果见[CONTROLROOM-004任务](../tasks/CONTROLROOM-004.md)及[验证](../validation/CONTROLROOM-004.md)。既有对照脚本`node --import tsx scripts/controlroom-validation.ts`检查50种子新旧启动一致性。

## 小地图与多楼层视图（MINIMAP-001）

正式计时后右侧显示倒计时与小地图；小地图方向固定；当前规模楼层默认全层居中，按实际画幅等比适配并留出图标边距，超大楼层按局部范围跟随。卡片可切换“全层／附近”，边缘目标带方向提示。实际行走路径来自当前Activity；下楼连接显示入口、出口及进度，不把初始方案当作执行路线。路线默认开启，可关闭并保存本机显示偏好。

M或展开按钮打开整站图，可缩放/拖动、切换楼层、用方向按钮平移及回到主角；Escape关闭。展开沿用原计时/暂停状态。手机默认折叠，二维降级同样可用。人物和设施故障只显示现行规则允许观察的状态，不读取隐藏队伍或未来事件。

`stationMap.ts`将WorldDefinition适配为通用StationAtlas：字符串楼层ID、名称/高度/范围、几何/设施和显式连接；`FloorMap.tsx`共用静态底图与动态层，创建预览和运行小地图同源。Atlas缓存归属世界对象，世界之间不共用导航/动态状态。当前双层生成器的专用几何留在适配器，绘制及楼层选择不依赖B1/B2枚举。

报告回放使用报告中的地图和过去轨迹，缺少实时路径记录的旧报告不推测未来路线。六层夹具只验证地图组件，不改变现有模拟层数。范围和证据见[任务](../tasks/MINIMAP-001.md)与[验证](../validation/MINIMAP-001.md)。

取景完整性与居中修正见[MINIMAP-002](../tasks/MINIMAP-002.md)及[验证](../validation/MINIMAP-002.md)。

小地图设施标记使用约12像素的紧凑样式，展开图仍保持18像素。可直接在小地图上滚轮缩放（鼠标指向位置为锚点，65%–1200%），拖动平移；双击或右下复位按钮恢复默认取景。切换楼层或全层/附近后也恢复该视图的默认比例。相关范围和证据见[MINIMAP-003](../tasks/MINIMAP-003.md)与[验证](../validation/MINIMAP-003.md)。

## V2 可玩建筑样板（WORLDGEN-V2-001，来源分支历史）

本节记录建筑分支的历史快照；同名细节V2与建筑V2现由摘要分别恢复，当前融合入口见下节V3。

内部开关 `?worldgen=v2` 创建metro-v2固定样板，默认仍为metro-v1。72米双端站厅、14米岛式站台、0/−6米标高，站厅/站台初始净高3.6/3.4米，仅为游戏美术比例。建筑区域并集、设备房、内部柱列及两个楼扶梯组来自同一静态定义；洞口、围护、模拟碰撞、小地图和展厅使用连接器ID派生。`traverse.connectorId`对V2工具显式提供，旧调用省略时按合法可达路径选择同类连接器，稳定ID打破平局。每个扶梯独立排队和准入，跨层活动和轨迹绑定ID。

上层不再因主角开始下楼而整组隐藏；正常视角保留建筑围合，总览单独剖切。顶面、梁带、灯槽、柱网、设备体块与连续屏蔽门建立空间层次；车门开口/编号来自既有共享列车门数据，沿用停靠开门状态与实际登车结算。无新时刻表、线路或方向玩法。

世界库外层格式保持不变，V2按生成版本/种子/摘要校验；旧版入口和旧报告保留。当前是M1原型，改变建筑定义后旧原型会提示不兼容并提供创建副本；不静默覆盖存档。M2三类随机布局及M3默认切换必须等待用户视觉确认。范围、调研来源和接手步骤见[任务简报](../tasks/WORLDGEN-V2-001.md)，实际成绩和未验收项见[验证报告](../validation/WORLDGEN-V2-001.md)。

## V3 建筑与日常设施融合（WORLDGEN-V3-001）

`?worldgen=v3`创建融合样板，默认保持来源细节V2。V3以建筑区域、设备房/内部柱列、四连接器和独立队列为底座，复用90个正式日常设施模型。种子1包含66处安装；实体、使用空间、队列和洞口先满足合法占地，再决定装饰变体。墙面/顶挂件按本层净高安装，不复用旧6米顶面的固定高度。每站只保留一套与列车实际开口一致的屏蔽门。

世界定义同时承载architecture、connectors和props，模拟、镜头、创建预览、正式3D、展厅、二维及小地图共用；模型工具在有连接器ID的地图中显式枚举ID，静态连接公开，动态队伍仍按现场可见性提供。布局/安装与装饰使用独立随机流，不消耗客流/运营流。

| 生成版本 | 恢复规则 |
|---|---|
| legacy-v0 | 保留旧构造和旧报告 |
| metro-v1 | 保留当前与历史摘要恢复 |
| metro-v2（细节来源） | 原随机布局与物件生成；摘要匹配 |
| metro-v2（建筑来源） | 固定双层建筑兼容工厂；摘要匹配，种子1仍为acc3b052 |
| metro-v3 | 建筑与细节融合；生成版本/种子/摘要一致才准备和恢复 |

未知版本或不匹配摘要提示创建当前版本副本，原记录保留。当前V3仍为视觉审核样板；新三类建筑随机生成与默认切换沿用用户原计划的视觉确认出口。旧随机布局、150秒默认、额外排队人数及实际登车规则不变。

范围与基线见[任务简报](../tasks/WORLDGEN-V3-001.md)，实际结果、短片/镜位证据及未验证矩阵见[验证报告](../validation/WORLDGEN-V3-001.md)。批量脚本为 `node --import tsx scripts/worldgen-v3-validation.ts`。
